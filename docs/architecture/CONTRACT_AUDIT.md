# Cross-component contract audit

Date: 2026-11-22. Scope: every boundary where two components agree only by convention (ids, LiveKit names and topics, Redis names and payloads, HTTP shapes, units, enums). Method: for each boundary the producer and the consumer were read in code and compared field by field; findings are about the code as it is at `0b0b6e0`, nothing was run against a live LiveKit or a live Redis (items that need a live check say so).

Severity: **BROKEN** = fails or silently loses data at runtime. **RISK** = works by accident, in one configuration, or only after a manual step. **OK** = verified equal on both sides (listed for the important boundaries so nobody re-audits them).

The bug that started this audit (LiveKit identity = user id vs pipeline speaker = participant id) is fixed in `0b0b6e0` and is listed as OK-02.

Counts: BROKEN 14, RISK 14, OK 13, plus section 3 (boundaries with no producer or no consumer).

---

## 2. Test strategy that would have caught these

The shared root cause is that each side is tested with its own fake. Replace the fakes at the seams with the other side's real producer:

1. **Golden fixtures from real producers.** A cargo test in `apps/pipeline/tests/contract_fixtures.rs` runs the real `TranslateDubStage` and `RedisResultSink` (or a recording `MediaSession`) with a scripted fake STT/MT/TTS and writes `captions.jsonl`, `published_tracks.json`, `stt_results.jsonl` to `apps/web/src/lib/__fixtures__/` and `apps/macos/Tests/Fixtures/`. Web (`parseCaption`/`mergeCaption`/track predicate) and Swift tests load them. CI fails when the Rust output changes and the fixture is not regenerated and re-consumed.
2. **Real room API into the real pipeline.** One test in `apps/api/tests/` builds the API router (real `RedisRoomEventPublisher`, real meeting join for tokens), creates a room, joins two users, starts it, then decodes the issued LiveKit tokens' identities and feeds the resulting Redis snapshot into `RoutesView`, and feeds audio with `MediaEvent::Audio { participant: <identity from the token> }` into `PipelineHost` with a recording `ResultSink`. This is the test that would have caught the original identity bug.
3. **Pipeline output into the real transcript service.** `apps/worker/tests/`: run the pipeline downstream with a `RedisResultSink`, run the real transcript consumers on Postgres, call `GET /transcripts/{room}`, assert speaker name, offsets, confidence, all chunks of a translation (B-05..B-07, R-02, R-03).
4. **Lifecycle test.** API `POST /meetings/{id}/end` with a recording `RoomService` and real Redis: assert room `ENDED`, `RoomEnded` on the commands channel, pipeline room worker stops, lease released (B-08, B-10).
5. **Static check for names.** Move every LiveKit name (track prefix, topics `captions`/`chat`/`reactions`, agent prefixes) and every Redis key/channel into `warptalk-contracts` and add a script that greps `apps/web/src` and `apps/macos/Sources` for hard-coded copies and compares them to the Rust constants (`scripts/check-contract-names.sh`).
6. **Live LiveKit smoke** (nightly, with the dev server in `deploy/`): two headless clients (livekit-client in Node), the pipeline with simulated STT/TTS, assert dub track visibility, captions delivery and hidden-agent behaviour (R-01).

### 3.3 Features whose output never reaches a user

1. AI suggestions (stream `ai_assistant:results`): no delivery, no UI.
2. Stored transcripts, translations, dubbing metadata: persisted (with the problems above) but no web/macOS screen reads `/transcripts/*`; the only reader is RAG search, which is gated off by B-13 for transcripts.
3. Transcript embeddings (`source_type=transcript`): gated by `aiRetrievalAllowed` (B-13) and skipped for early segments (R-03); members additionally filtered out (R-10).
4. Route degradation (`ROUTE_DEGRADED`), billing stop, summaries, follow-ups: published or planned, no consumer.
5. Host moderation pushes (lobby, kick, lock, host transfer): the web polls REST instead (`useParticipants`), so lobby and removal work only by polling and removal never reaches LiveKit (B-10).
